# 无驱动控制 HA：场景桥

目标：**不往 HDL 网关安装任何驱动**，让 Studio / HDL App / 面板能控制 Home Assistant 里的实体。

---

## 思路

集成把 HA 侧要暴露的实体在网关里注册成一对「场景」：`<名称> 开` / `<名称> 关`，两条都绑到同一个 HA 实体。
HDL 侧执行场景时，集成会收到该场景的执行事件，按绑定关系调用 `turn_on` / `turn_off`。

这样 HDL 侧看到的是场景而不是设备卡片，但不需要驱动、不需要改网关固件，也不占网关额外资源。

---

## 用法

### 1. 生成场景桥

开发者工具 → 动作：

```yaml
action: hdl_link.scene_bridge
data:
  entity_id: light.keting
  name: 客厅灯          # 选填，作为场景名前缀；留空用实体名称
  # entry_id: 多网关时指定
```

它做三件事：

1. 按实体稳定生成这对场景的标识（同一实体每次调用都一样，可重复执行）；
2. 在网关里建两条空动作场景：`<名称> 开` / `<名称> 关`；
3. 把两条场景分别绑成 `turn_on` / `turn_off`。

返回值：

```json
{
  "entity_id": "light.…",
  "label": "客厅灯",
  "scenes": [
    {"name": "客厅灯 开", "add_msg": "Success", "present": true},
    {"name": "客厅灯 关", "add_msg": "Success", "present": true}
  ]
}
```

`present=true` 表示回读网关场景列表时这两条确实存在；只要有一个 `false`，就别接着用，先看日志。

### 2. 在 HDL 侧使用

- **Studio / App**：场景列表里会多出这两条，直接点执行；
- **面板**：把按键绑到这两条场景（按键 → 场景），按一下开、另一下关（或按面板键值分别绑开/关场景）。

### 3. 拆除

```yaml
action: hdl_link.scene_bridge_remove
data:
  entity_id: light.…
```

删除网关里这两条场景，并清掉绑定。

---

## 为什么用「空动作场景」

场景本身不带任何设备动作 —— 它的价值只是「被执行时集成会收到一次事件」。
所以不要在场景里塞 HDL 设备动作，否则会额外动真实回路。

---

## 局限（务必先看清）

- HDL 侧看到的是**场景**，不是一台设备卡片；面板按键要绑到场景而不是"设备"。
- 一个实体占**两条**场景，而网关的场景总量只有约 5 条，新增会挤掉最早的 → 实际上只适合 2 个实体。需要更多实体时要考虑换固件或另找通道。
- 开/关分成两条场景（事件本身不带具体数值），亮度 / 色温这类连续控制做不了。
- 场景里自带的动作不能指向 HA 虚拟设备，只能指向真实 HDL 设备。
- HA 的虚拟设备（用于把 HA 状态同步回 HDL）仍然保留，App 里能看到状态。

---

## 排障

| 现象 | 处理 |
|---|---|
| `present=false` | 场景没真正落库：网关场景数量已满，先删掉不用的场景再重试 |
| HDL 侧看不到新场景 | 在 Studio 里重新读取一次工程 / 刷新场景列表 |
| 点了场景 HA 不动 | 看 HA 日志里是否有「上行批次 kind=scene」与「控制已下发」；没有就是事件没到，先确认集成在线 |
| 只有开或只有关生效 | 另一条场景被顶掉了，重新调一次 `scene_bridge` 看 `present` |
